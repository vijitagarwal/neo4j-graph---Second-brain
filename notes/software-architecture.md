# Software Architecture

Software architecture describes the major structural decisions in a system. A layered architecture separates presentation, business logic, and data access. An event-driven architecture coordinates components using asynchronous messages. Microservices improve scalability by decomposing systems into independent services.

A service mesh helps manage traffic, observability, and security between services. Interfaces and contracts define how components interact, and domain boundaries keep responsibilities clear. A good architecture balances performance, maintainability, and reliability.

Architects often rely on APIs, message brokers, and load balancers to manage communication and scale. A monolith may be simpler to deploy, while distributed systems offer flexibility for complex workloads.
